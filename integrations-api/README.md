# Graph integrations Worker

The production Worker is `https://atom-integrations-api.archimedes-api1.workers.dev`. Its **public, read-only graph JSON download** powers the Dropbox Saver button in Proof Lab. The deployed configuration contains no OAuth secrets, so direct Google Drive API upload is unavailable. Google's Save to Drive button was tested but its authentication popup remained blank and no file appeared in Drive, so the site retains an honest manual Google Drive download instead. Notion, GitHub, Dropbox API export, and Zapier API export are deliberately unavailable; no endpoint sends data to them. Dropbox Saver fetches the user-approved public graph file URL directly. Anyone with that URL can read its graph content.

The Dropbox app is `atomEDU Proof Lab`, with public app key `ajyniy3x7a5h1yl`. Its registered Saver domains are `atom-edu.org` and `localhost`. The app secret is not used or stored in this codebase. The Saver supports up to 24 expressions and a bounded URL; larger graphs retain a local JSON download option.

## Setup

1. The current `wrangler.jsonc` deploys the public download only on `workers.dev`. For future Google Drive OAuth, configure an HTTPS API origin under the same site as the frontend, e.g. `https://integrations.atom-edu.org`, routing `/api/integrations/*` to this Worker. Set `API_ORIGIN` to that exact origin. The browser will need `credentials: 'include'`; the API must be same-site so `SameSite=Lax` cookies work. Do not set OAuth secrets before this routing exists.
2. In Google Cloud, configure the OAuth consent screen, enable the Drive API, and create a **Web application** OAuth client. Set its authorized redirect URI to `https://integrations.atom-edu.org/api/integrations/oauth/drive/callback` (substitute the actual API origin). Request `https://www.googleapis.com/auth/drive.file`; Google's OAuth verification rules may apply. Add test users while the consent screen is in testing mode.
3. Set Worker secrets `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, and `SESSION_SECRET` (at least 32 characters, random). Do not put them in `vars` or client code. Keep the session secret stable across deployments or existing sessions will end. Without any of these or valid origins, Drive OAuth is unavailable. The read-only download needs only a valid `ALLOWED_ORIGIN` and both rate limiting bindings; it does not need `API_ORIGIN`, `SESSION_SECRET`, or Google credentials. No service account or global Drive credential is used.
4. Configure both Cloudflare Rate Limiting bindings in the example config. Replace namespace IDs `1001` and `1002` with unique IDs for the account. The per-IP bucket permits 30 requests/minute and the shared bucket permits 1000 requests/minute per Cloudflare location. Cloudflare documents these as approximate limits, not a strict global quota. If either binding is absent, `/download` returns 503.
5. Review the frontend's opt-in UI. Show a destination and request consent before navigating to the OAuth start route. After the callback redirects to `/proof-lab#graph`, fetch status again. The frontend must explicitly call export; OAuth alone never exports.

The *unconfigured* OAuth flow uses a 10 minute encrypted state/PKCE cookie and a short-lived encrypted, Secure, HttpOnly, SameSite=Lax token cookie. Tokens are held only in that browser's cookie, with no refresh token. The user can disconnect locally; Google access tokens also expire. For immediate Google-side revocation, the user can revoke the app in their Google Account. Browser cookie limits and third-party cookie restrictions are why same-site routing is required.

## Route contract

Base path: `/api/integrations` on the deployed Worker. All JSON responses use `Cache-Control: no-store`. OAuth/status CORS allows credentials only from the exact `ALLOWED_ORIGIN`. The public `/download` file has wildcard CORS and no credentials so the provider widgets can fetch it; possession of its URL already reveals the graph content.

- `GET /status` → `200 {"providers":{"drive":{"available":true,"connected":false},"notion":{"available":false,"connected":false,"reason":"unsupported"},"github":…,"dropbox":…,"zapier":…}}`. Drive becomes `available:false,reason:"missing_config"` if configuration is incomplete. For an authenticated request from `ALLOWED_ORIGIN`, `drive.connected` is true and a top-level `csrfToken` is included. Send `Origin` and `credentials: 'include'` from the frontend. No secret or OAuth token is returned. A top-level `download` field is `{"available":true}` when `ALLOWED_ORIGIN` is a valid exact HTTPS origin and both rate limiting bindings exist, otherwise `{"available":false,"reason":"missing_config"}`. This remains true without any OAuth configuration.
- `GET /download?graph=<encodeURIComponent(JSON.stringify(graph))>` → `200` with actual graph JSON, `Content-Type: application/json; charset=utf-8`, `Content-Disposition: attachment; filename="atom-graph.json"`, and `Cache-Control: no-store`. No cookies or Origin are needed for provider fetches; wildcard CORS plus `OPTIONS` support allows Save to Drive to fetch the public file. The sole query parameter must be `graph`; the URL is capped at 8192 characters and decoded and normalized graph JSON at 4096 UTF-8 bytes. Structural graph limits match `/exports`. `429 rate_limited` when either Cloudflare rate limiting binding denies the request; `503 download_unavailable/missing_config` without a valid `ALLOWED_ORIGIN` or both bindings; `414 url_too_long`, `413 graph_too_large`, `400 invalid_graph` or `400 invalid_request` for invalid input. No persistence or outbound fetch occurs. This URL is public and exposes the graph to anyone who obtains it, including the selected widget provider. The frontend should create it only after the user chooses that provider.
- `GET /oauth/drive/start` → `302` to Google's consent page with a state and S256 PKCE challenge. Use top-level navigation. `503 {"error":"provider_unavailable","reason":"missing_config"}` if not configured.
- `GET /oauth/drive/callback` → Google redirect URI. Validates state and exchanges the code, then `302` to `${ALLOWED_ORIGIN}/proof-lab#graph`. `400 oauth_invalid` for invalid state. Tokens never enter the redirect URL.
- `POST /exports` with `Origin: <ALLOWED_ORIGIN>`, `Content-Type: application/json`, `X-CSRF-Token: <status.csrfToken>`, cookies, and body `{"provider":"drive","graph":{"v":1,"expressions":[{"expression":"y=x^2"}]}}` → `201 {"provider":"drive","id":"<Drive file id>","url":"https://drive.google.com/file/d/<id>/view"}` after Drive confirms creation. The graph is a JSON file in the consenting user's Drive, private by default. Body maximum is 16 KiB; graph follows the bounded public graph state fields. Missing OAuth: `401 not_connected`; bad origin or CSRF: `403`; bad graph: `400`; oversized body: `413`; Drive failure: `502 provider_error`; missing Drive config: `503 provider_unavailable/missing_config`; Notion/GitHub/Dropbox/Zapier: `501 provider_unsupported/unsupported`.
- `POST /oauth/drive/disconnect` with the same Origin, CSRF header and cookies → `200 {"provider":"drive","connected":false}` and clears the local token cookie. This does not revoke the Google token remotely.
- `OPTIONS /exports` and `OPTIONS /oauth/drive/disconnect` → `204` for the allowed origin; `403` otherwise.

The Worker never accepts a destination URL, arbitrary provider endpoint, raw access token, or service account credential from the request. Provider HTTP responses are bounded before parsing. The graph payload is structurally validated; it is not re-parsed as math, and the exported JSON is data, not an evaluated expression.

## Official API references checked

- [Google Save to Drive button](https://developers.google.com/drive/api/guides/savetodrive) and [Dropbox Saver](https://www.dropbox.com/developers/saver) — both need frontend widget integration; Dropbox also requires an app key. The download URL is only the source file.
- [Cloudflare Rate Limiting binding](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)
- [Google OAuth web-server flow](https://developers.google.com/identity/protocols/oauth2/web-server) and [OAuth for mobile and desktop apps (PKCE concepts)](https://developers.google.com/identity/protocols/oauth2/native-app)
- [Google Drive file creation](https://developers.google.com/drive/api/reference/rest/v3/files/create), [multipart upload](https://developers.google.com/workspace/drive/api/guides/manage-uploads), and [Drive scopes](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)
- [Notion public integration authorization](https://developers.notion.com/docs/authorization), [GitHub OAuth app authorization](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps), [Dropbox OAuth guide](https://developers.dropbox.com/oauth-guide), and [Zapier platform authentication](https://docs.zapier.com/platform/build/auth) — these are research references only. No flow for these providers is implemented or claimed live.
- [Cloudflare Workers best practices](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/)
